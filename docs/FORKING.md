# Forking this repository

This guide shows how to run your own copy of this repository. Your fork builds its
own Stable and Main images and publishes its own Home Assistant app store.

> **Only want to install Nocturne?** You do not need a fork. In Home Assistant, add
> `https://github.com/smokkelaar/nocturne-home-assistant-upstream#home-assistant`
> as an app repository. See [SETUP.en.md](SETUP.en.md).

## How the repository works

| Part | Where | What it does |
| --- | --- | --- |
| Source | `main` branch | Wrapper code, tests, tools and workflows |
| App store | `home-assistant` branch | Generated by the pipeline. Contains `repository.yaml`, `stable/` and `main/`. Do not edit it by hand. |
| Images | GHCR: `ghcr.io/<owner>/<repo>/nocturne-<channel>-<arch>` | Built and tested by the pipeline |
| Runners | GitHub-hosted `ubuntu-24.04` and `ubuntu-24.04-arm` | No self-hosted runners are needed |

The workflows use `${{ github.repository }}`. Your fork automatically publishes to
its own images and branch. You do not need to change any owner names.

## Why a fresh fork seems broken

1. **No `home-assistant` branch.** GitHub copies only `main` by default. This is
   expected. The first successful publication creates the branch.
2. **No workflow runs.** GitHub disables Actions in new forks until you enable them.
   Scheduled runs also stay off until you enable them.
3. **Private images.** GHCR packages can start private. The pipeline must pull them
   anonymously, and so must Home Assistant.

## Steps

### 1. Create the fork

1. Open the repository and select **Fork**.
2. Keep **Copy the `main` branch only** selected (recommended).
3. Keep the fork **public**. Free ARM64 runners (`ubuntu-24.04-arm`) are only
   available to public repositories. Public images also let Home Assistant install
   without registry credentials.

If you copied all branches, delete the copied `home-assistant` branch in your fork
before the first run. Otherwise, the store keeps pointing to smokkelaar's images.
The pipeline also sees those versions as already published and skips them.

### 2. Enable GitHub Actions

1. In your fork, open the **Actions** tab.
2. Select **I understand my workflows, go ahead and enable them**.
3. Open **Publish Home Assistant Stable and Main**. If GitHub shows a scheduled
   workflow warning, select **Enable workflow**.
4. Under **Settings → Actions → General**, allow **all actions and reusable
   workflows**.

You do not need to add secrets. The workflows use the built-in `GITHUB_TOKEN` and
set their own permissions. These include `packages: write` for image builds and
`contents: write` for the store branch.

### 3. Run the first publication

1. Open **Actions → Validate Home Assistant wrapper → Run workflow**, select
   `main`, and wait for a green result.
2. Open **Actions → Publish Home Assistant Stable and Main → Run workflow**, select
   `main`, and start the run. You can leave **force** off for the first run.
3. The run builds and tests AMD64 and ARM64 images for Stable and Main, verifies
   anonymous pulls, and creates the `home-assistant` branch.
   The first run has no previous version, so the recovery test uses the new image.

If a channel says **deferred**, Nocturne itself is still publishing that source.
The hourly schedule tries again automatically.

### 4. Make the images public if needed

If the first publish run fails at the anonymous pull or promotion step:

1. Open your GitHub profile → **Packages**. Repeat these steps for each
   `nocturne-stable-*` and `nocturne-main-*` package.
2. Open **Package settings → Change visibility → Public**.
3. Re-run the failed jobs.

### 5. Add your fork to Home Assistant

In Home Assistant, open **Settings → Apps → App store**. Open the **⋮** menu,
select **Repositories**, and add:

```text
https://github.com/<your-account>/<your-repository>#home-assistant
```

The `#home-assistant` suffix is required. Do not add both the original and your fork
to the same Home Assistant instance. Both offer apps with the same names and ports.

## Keeping the fork up to date

- New Nocturne releases and Main snapshots publish automatically every hour.
- To receive wrapper fixes from this repository, select **Sync fork** on your
  fork's `main` branch. Do not sync or merge `home-assistant`; your pipeline owns
  that branch.
- GitHub disables schedules in repositories without activity for 60 days. If that
  happens, enable the workflow again on the Actions tab.
- To rebuild unchanged versions, for example after base-image updates, run
  **Publish Home Assistant Stable and Main** with **force** turned on.

## Optional customization

- README badges and links still point to `smokkelaar`. Update them in your fork for
  correct status badges.
- `repository.yaml` is generated on every publication. Its URL and maintainer come
  from your repository. Its name is always `Nocturne Home Assistant (experimental)`
  (`deploy/home-assistant/tools/publish_store.py`). Do not edit the generated file;
  change that tool if you want a different store name.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| No workflows ran | Actions are disabled in the fork | Step 2 |
| Branch `home-assistant` is missing | Nothing has been published yet | Step 3 |
| ARM64 jobs stay queued | The fork is private | Make the fork public |
| Anonymous pull or `denied` error | GHCR package is private | Step 4 |
| `Resource not accessible by integration` | Actions permissions are restricted by an organization policy | Allow the workflow permissions in organization settings |
| Run succeeds but nothing is published | Channel is unchanged or deferred | Wait for the hourly schedule, or use **force** |
| HA shows smokkelaar's versions | A copied store branch was used, or the URL is wrong | Delete the copied branch and publish again; check the HA repository URL |
